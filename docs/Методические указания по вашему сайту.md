# Методические указания по созданию и поддержке проекта учебной платформы (Vite + React + Tailwind + Node API)

## 1. Цель разработки
- Создать учебную платформу для регистрации, прохождения тем и заданий, отслеживания прогресса и администрирования контента (темы, задания, пользователи).
- Обеспечить удобную модерацию и поддержку со стороны администраторов и супер-администраторов.

## 2. Подготовительный этап
### 2.1. Определение функционала проекта
- Программа обучения: темы и задачи (страницы `Topic`, `Task`, `Tasks`).
- Прогресс: визуализация и история (`Progress`, `HistoryList`).
- Аутентификация: роли `User`, `Admin`, `SuperAdmin` (страницы `Login`, `Register`, `Admin`, `SuperAdmin`).
- Администрирование: управление темами, заданиями и пользователями (`AdminPanel`, `AdminTabs`, `TopicsAdmin`, `TasksAdmin`, `UsersList`).
- Анти-чит инструменты: баннер и хук (`AntiCheatBanner`, `useAntiCheat`).
- Общие компоненты UI: модальные окна, выпадающие меню, прогресс-бар, переключение темы (`Modal`, `DropdownMenu`, `ProgressBar`, `ThemeToggle`, `theme.jsx`).

### 2.2. Выбор технологий
- Фронтенд: Vite + React (JSX), `tailwindcss` для стилизации.
- Анимации: базовые CSS-транзишны; при необходимости — `framer-motion`.
- Бандлинг: Vite (конфиг в `vite.config.js`).
- Стили: Tailwind (конфиги `tailwind.config.js`, `postcss.config.js`, стили в `src/index.css`).
- Сервер: Node.js + Express (файлы в `server/`: `server.js`, `auth.js`, `db.js`, `seed.js`).
- База данных: определяется реализацией в `server/db.js` (рекомендуется SQLite/PostgreSQL). 
- Клиент–сервер API: функции в `src/lib/api.js`.

### 2.3. Использование ИИ-агентов
ИИ-агенты применяются для:
- генерации UI-компонентов на Tailwind;
- написания серверных роутов и валидации входных данных (например, через `zod`);
- создания контента (тексты тем/заданий), подсказок и описаний;
- рефакторинга клиентских и серверных слоёв, оптимизации запросов и рендеринга.

## 3. Инструкции для ИИ-агентов
### 3.1. Общий принцип
- Соблюдать разделение: клиентские компоненты в `src/`, API-роуты и бизнес-логика в `server/`.
- Не смешивать серверную логику в React-компонентах; все обращения к БД — через `server/db.js` и соответствующие маршруты.

### 3.2. Примеры инструкций
- Для бэкенда:
  - «Создай POST-маршрут `/api/submissions`, который валидирует данные через `zod`, сохраняет решение задачи в БД и возвращает обновленный прогресс пользователя.»
  - «Добавь эндпоинт `/api/topics` с фильтрацией и пагинацией; обеспечь доступ только администраторам при создании/редактировании.»
- Для фронтенда:
  - «Напиши компонент `SubmissionsList` с виртуализацией длинных списков и индикаторами статуса отправки.»
  - «Добавь анимации появления в `Tasks` и `Topic` с использованием `framer-motion` (если установлен).»
- Для БД:
  - «Расширь схему БД: добавь таблицу `Certificates` и миграции; обнови `seed.js` для тестовых данных.»

## 5. Работа с базой данных
- Предпочтительно использовать SQLite или PostgreSQL; конфигурация и подключение — в `server/db.js`.
- Основные сущности:
  - `User` — пользователи, роли (User, Admin, SuperAdmin).
  - `Topic` — темы обучения.
  - `Task` — задания (связь с темами).
  - `Submission` — отправки решений.
  - `Progress` — агрегированный прогресс пользователя.
  - При расширении: `Certificate` — сертификаты завершения.
- Роль ИИ-агентов:
  - формировать безопасные запросы (без сырого SQL, с параметрами);
  - оптимизировать индексы и связи;
  - генерировать сиды в `server/seed.js` для тестовых данных.

## 6. Тестирование и отладка
### 6.1. Методы
- Валидация: добавить `zod` на клиенте и сервере для строгой проверки входных данных.
- Ошибки рендеринга: использовать `ErrorBoundary.jsx` для перехвата ошибок UI.
- Производительность: следить за лишними ререндерами, мемуизировать тяжелые списки.

### 6.2. Примеры задач для ИИ
- «Проверь компонент `Tasks` на лишние ререндеры; предложи `useMemo`/`useCallback` там, где это оправдано.»
- «Напиши тест-кейс доступа: скрывать админ-панель пользователям без роли Admin/SuperAdmin.»

## 7. Инструкции по взаимодействию с ИИ
- Контекст: всегда указывать, что фронтенд — React (Vite), сервер — Node/Express, API — в `server/`.
- Безопасность: проверка прав в серверных маршрутах (middleware), не доверять данным с клиента.
- Стиль: использовать единые утилиты из `src/lib/api.js`, не дублировать сетевые вызовы в компонентах.
- Сессии/аутентификация: централизовать в `server/auth.js`; клиент получает статус через единый эндпоинт.

## 8. Итог
Проект — современное Fullstack-приложение на Vite + React + Node API.
Разработчик оттачивает навыки:
- архитектуры клиент–сервер с чётким разделением обязанностей;
- работы с реляционными БД и сидированием данных;
- интеграции ИИ-агентов для генерации компонентов, валидации и рефакторинга;
- создания отзывчивого UI на Tailwind с расширением анимаций по мере необходимости.
